# GONE 프로젝트 소개 & 팀 온보딩 가이드

이 문서는 두 가지 역할을 해요. 하나는 새로 합류할 사람에게 프로젝트를 소개하고 설득하는
자료, 다른 하나는 합류를 결정한 사람이 파트(백엔드/프론트엔드/디자인/기획 등)와 상관없이
가장 먼저 파악해야 할 내용을 정리한 자료예요. 파트별 세부 실무는 각자의 파트 문서/저장소에서
이어서 다루고, 여기서는 "이 프로젝트가 뭐고 어떻게 협업하는지"까지만 다뤄요.

GitHub 조직: `GBSW-ReMake`

---

## 1. GONE이 뭐냐면

경북소프트웨어고등학교(GBSW) 학교생활을 위한 서비스예요. 지금 학교에서 종이, 엑셀,
카톡방으로 굴러가는 절차들 — 외출증, 상/벌점, 급식·시간표 확인, 월례 행사(스쿨캠핑) 신청
— 을 하나의 앱과 서버로 옮기는 게 목표예요.

그냥 "종이를 화면으로 옮기는" 프로젝트는 아니에요. 외출 기능을 예로 들면, 처음 던진 질문은
"선도부가 정문에서 학생을 막아 세워 확인하던 방식을 서버가 실시간으로 대체할 수 있을까"였어요.
그 결과 학생이 출발·도착을 직접 신고하되 GPS로 학교 반경 안인지 그 자리에서 검증하고,
선도부·담당 선생님은 "지금 누가 나가 있는지"를 실시간 목록과 동선으로 확인하는 쪽으로
역할이 바뀌었죠. "수기 확인"을 "실시간 가시성"으로 바꾸는 게 이 프로젝트 전체를 관통하는
문제의식이에요.

### 지금 다루는 기능들

| 기능 | 상태 | 한 줄 설명 |
|---|---|---|
| 인증/계정 | 완료 | 회원가입, 로그인, 휴대폰 인증, 프로필(닉네임/실명/프로필 사진) |
| 급식/시간표 | 완료 | 학교 NEIS(교육정보시스템) 연동 조회 |
| 외출증 | 설계 완료, 단계적 구현 중 | 신청 → 담당 선생님 승인 → 학생 본인 출발/도착 신고(위치 검증) → 선도부/선생님 실시간 조회 |
| 알림 | 착수 | 인앱 알림함 + 푸시(보조) — 외출/스쿨캠핑/상벌점이 공유해서 쓸 공통 인프라 |
| 스쿨캠핑 | 기획 완료, 구현 전 | 선생님 1명 + 학생 최대 8명이 함께하는 월례 행사, 선착순 신청 |
| 상/벌점 | 기획 완료, 구현 전 | 생활 태도 기록 부여 및 조회 |

이 저장소(`GONE-server-V1`)는 그중 서버(백엔드) 파트를 담당해요. 기능별 세부 설계는
`docs/domain/{기능명}/` 아래 기획서에 정리돼 있고, 어떤 파트로 합류하든 자신이 다룰 기능의
마스터 기획서(`1_{기능명}-domain.md`)를 먼저 읽으면 "왜 이렇게 만들었는지"가 대부분 설명돼
있어요.

위 표는 어디까지나 MVP예요. 여기서 끝낼 생각으로 시작한 게 아니라, 학교생활 전체를
커버하는 방향으로 계속 확장할 계획이에요. 지금 논의되고 있는 것만 해도 기숙사 관리, 동아리
관리, 야자(야간자율학습) 현황표 관리 같은 기능들이 있고, 이런 것들이 순차적으로 추가될
예정이에요. 즉 지금 합류하면 이미 정해진 기능을 구현만 하고 끝나는 게 아니라, 앞으로 나올
기능들의 기획 단계부터 계속 참여하게 된다는 뜻이에요.

## 2. 캡스톤·해커톤이랑 뭐가 다르냐면

캡스톤이나 해커톤은 보통 짧게 만들고 발표하고 나면 그걸로 끝이에요. 실제로 누가 쓰지도
않고, 만든 사람이 계속 운영하지도 않으니까 "서비스를 다룬다"는 경험 자체가 남지 않아요.

GONE은 달라요. 실제로 재학생과 선생님이 쓰는, 지금도 돌아가고 있는 서비스예요. 그래서
여기서 얻는 경험은 "화면 몇 개 붙여서 데모 시연"이 아니라, 실사용자를 상대로 배포하고,
장애를 대응하고, 요구사항이 바뀌면 기존 코드를 유지보수하는 것까지예요. 캡스톤에서는 배울
수 없는 부분이죠.

그리고 저희는 완성된 걸 던져주고 "이제부터 너희가 관리해"라는 식으로 팀원을 모으지 않아요.
기획 단계부터, 코드 한 줄 짜는 단계부터 같이 시작해요. 처음부터 같이 만든 기능이어야
나중에 유지보수든 운영이든 "내가 만든 거니까 내가 책임진다"는 감각이 생긴다고 생각하거든요.
이미 만들어진 코드를 인수인계 받는 것과, 처음부터 설계에 참여해서 만든 코드는 애정도
자체가 달라요.

## 3. 같이할 사람을 찾아요

실사용자가 있는 서비스를 기획부터 배포, 운영까지 직접 끌고 가보고 싶은 사람을 찾고 있어요.
파트는 백엔드/프론트엔드/디자인/기획 등 프로젝트가 필요로 하는 여러 파트로 열려 있고, 어느
파트든 공통적으로 아래 흐름 안에서 일해요.

기능 하나를 맡으면 "화면/코드 몇 개 만들기"로 끝나지 않아요. **문제 정의 → 기획서 작성 →
팀 리뷰 → 작업 → 검증(QA) → 결과 보고 → 공유 문서 반영**까지 한 사이클을 직접 끝까지
끌고 가요.

예를 들어 외출 기능 하나에도 "정원이 있는 자원을 여러 사람이 동시에 신청하면 어떻게
안전하게 처리할지", "위치 정보를 어디까지 신뢰할지", "실시간성을 어느 수준까지 구현할지"
같은, 정답이 하나로 정해져 있지 않은 판단들이 계속 나와요. 그 판단을 문서로 남기고 팀과
맞춰가는 과정 자체가 이 프로젝트의 핵심 경험이에요.

### 이런 사람과 잘 맞아요
- 결정을 문서로 남기고 합의한 뒤 진행하는 흐름을 답답해하지 않는 사람 (반대로, 이 과정에서
  스스로 기획·설계력을 키우고 싶은 사람에게는 특히 잘 맞아요)
- Git/GitHub 협업(이슈, PR, 코드 리뷰)에 익숙하거나 배우고 싶은 사람
- 자기 파트만 보지 않고, 옆 파트가 왜 그렇게 설계했는지 궁금해하는 사람

### 참여하면 얻는 것
- 기획 → 설계 → 구현 → 검증 → 배포까지, 한 기능의 전체 생명주기를 반복 경험
- 코드/기획 리뷰를 거치는 협업 습관
- 실사용자가 있는 서비스를 처음부터 끝까지 직접 운영해본 이력
