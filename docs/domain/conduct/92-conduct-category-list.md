# 상/벌점 카테고리 목록 조회 — 기능 기획서 (이슈 #92)

## 개요/목적

교사가 상/벌점을 부여할 때 카테고리(사유)를 선택할 수 있도록, 사전 등록된 카테고리 목록을
조회하는 API를 구현한다. 이 이슈에서 `ConductCategory` 테이블(엔티티·마이그레이션·시드 데이터)을
처음 설립하므로, 이후 부여·정정·취소·이력 조회 이슈는 모두 이 인프라를 전제로 진행한다.

- 관련 이슈: #58 (상/벌점 도메인 마스터 기획서, `docs/domain/conduct/1_conduct-domain.md`)

## 엔드포인트

### `GET /api/v1/conduct-records/categories` — 카테고리 목록 조회

**권한**: 인증된 사용자 전체 (`@PreAuthorize("isAuthenticated()")`)

**요청**: 파라미터 없음

**응답** (`200 OK`)
```json
{
  "success": true,
  "data": [
    { "id": 1, "label": "봉사활동으로 교내 청소를 열심히 한 학생", "type": "MERIT", "points": 2 },
    { "id": 19, "label": "용의 규정을 위반한 학생(염색)", "type": "DEMERIT", "points": -5 }
  ],
  "message": "카테고리 목록을 조회했습니다.",
  "code": null
}
```

**구현 로직**
1. `conductCategoryRepository.findByActiveTrueOrderById()`로 활성(`active = true`) 카테고리
   전체를 `id` 오름차순으로 조회한다.
2. `ConductCategoryResponse` DTO 리스트로 변환해 반환한다.

**에러**: 없음 (인증 실패는 공통 인프라가 처리)

## 데이터 모델

### `ConductType` enum (신규)

| 상수 | 의미 |
|------|------|
| `MERIT` | 상점 |
| `DEMERIT` | 벌점 |

### `ConductCategory` 엔티티 (`conduct_category` 테이블, 신규)

| 컬럼 | 타입 | 제약 |
|------|------|------|
| `id` | `BIGINT` | PK, 자동증가 |
| `label` | `VARCHAR(500)` | `NOT NULL`, `UNIQUE` |
| `type` | `VARCHAR(20)` | `NOT NULL` (`MERIT`/`DEMERIT`) |
| `points` | `INT` | `NOT NULL` (부호 포함 — 상점은 양수, 벌점은 음수) |
| `active` | `BOOLEAN` | `NOT NULL`, 기본 `true` |
| `created_at` | `DATETIME` | `NOT NULL`, 자동 설정 |

> `label`을 `VARCHAR(500)`으로 설정하는 이유: 규정표 항목 중 가장 긴 사유 문구가 약 90자
> 수준이지만, 이후 관리자가 추가할 항목까지 고려해 여유를 둔다.

## 영향 받는 기존 코드

- `SecurityConfig` (`src/main/java/com/remake/gone/common/config/SecurityConfig.java`):
  `/api/v1/conduct-records/**` 경로를 `authenticated()` 규칙에 추가한다. 이 변경 없이는
  인증 없이도 카테고리 목록에 접근할 수 있어, 이 이슈의 첫 번째 작업 항목으로 처리한다.

## 리스크 및 고려사항 (API 설계 6원칙 체크)

1. **단일 책임**: 카테고리 목록 조회 하나만 담당한다. 부여·정정·조회는 별도 이슈로 분리했다.
2. **빠른 시작**: 응답 예시 포함. `id`를 그대로 부여 요청의 `categoryId`로 사용한다.
3. **일관성**: `ApiResponse<List<T>>` 래퍼, `isAuthenticated()` 패턴은 기존 도메인과 동일하다.
4. **의미 있는 오류**: 이 엔드포인트 자체의 오류 없음.
5. **확장성/성능**: 카테고리 목록은 최대 수백 건 수준 — 페이지네이션이 불필요하고 전체 목록을
   반환한다. `active = true` 조건에 인덱스는 현재 데이터 규모상 불필요하며, 이후 성능 이슈가
   실제로 발생하면 추가한다.
6. **하위 호환성**: 신규 도메인이므로 기존 응답에 변경이 없다.

**`label` UNIQUE 제약 리스크**: 규정표 항목 중 사유 문구가 완전히 동일한 항목은 없음을 확인했다.
향후 관리자가 추가하는 항목이 기존 표시명과 정확히 일치하면 DB 레벨에서 거부된다 —
카테고리 추가 API 구현 시 이 제약을 사용자에게 명확히 안내해야 한다(후속 이슈).
