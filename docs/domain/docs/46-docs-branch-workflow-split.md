# #46 branch-workflow.md 세부 규칙을 별도 rules 파일로 분리 — 기획서

관련 이슈: https://github.com/GBSW-ReMake/GONE-server-V1/issues/46

## 개요/목적
`docs/rules/branch-workflow.md`(현재 187줄)에 15단계 절차의 "순서"(무엇을 언제 하는가)와
일부 단계의 "세부 규칙"(어떻게 하는가)이 섞여 있다. 특정 세부 규칙만 참조하고 싶을 때도
전체 파일을 열어야 한다. 코드 변경은 없고 문서만 재구성한다.

## 분리 대상 확정 (이슈 원문의 예시 3개 그대로 채택)
현재 파일을 다시 읽고, 아래 4개 블록이 "절차 순서"가 아니라 "그 부분만 따로 참조할 만한
세부 규칙"이라고 판단했다(이슈 본문 예시 3개 + 관련성이 높아 같이 묶는 게 자연스러운 1개).

1. **"📋 진행 상태 추적(외부화)" 섹션**(현재 21~28줄) → `docs/rules/progress-tracking.md`
   (신규). 이슈 체크리스트로 진행 상태를 관리하는 방식 전체를 다룬다.
2. **"🚨 한 번에 하나의 기능만" 섹션**(현재 8~19줄) → 같은 신규 파일
   `docs/rules/progress-tracking.md`에 함께 담는다. 이슈 원문 예시엔 없지만, "왜 진행
   상태를 외부화하는가"와 "동시에 하나만 진행한다"는 정책이 서로 전제를 공유해서(체크리스트
   외부화가 "하나만 진행" 규칙을 세션이 끊겨도 지킬 수 있게 하는 수단이다) 같은 문서에
   두는 게 따로 두는 것보다 읽기 자연스럽다고 판단했다. 이견 있으면 알려달라 — 별도
   파일로 쪼갤 수도 있다.
3. **9단계 코드 리뷰의 컨텍스트 격리 규칙**(현재 102~114줄 중 세부 절차 부분) →
   `docs/rules/code-review-isolation.md`(신규). 이미 있는
   [code-review-template.md](../../rules/code-review-template.md)는 "리뷰 결과 문서
   형식"만 다루고, 이번에 분리하는 문서는 "격리된 에이전트를 어떻게 띄우는가"(무엇을
   넘기고 무엇을 넘기지 않는가)를 다뤄 대상이 겹치지 않는다.
4. **15단계 Postman 컬렉션 구조 규칙**(현재 145~167줄) → `docs/rules/postman-collection-structure.md`
   (신규). 최상위/사전 준비/에러 케이스/기능별 검증 폴더 구조 규칙과 예시를 담는다. 워크스페이스/
   API 키 위치 안내(164~165줄)는 반영 "시점/방법" 얘기라 구조 규칙과는 성격이 달라서, 이
   문서가 아니라 branch-workflow.md 15단계 본문에 한 줄로 남겨둔다.

**분리하지 않고 그대로 두는 것**: 2단계 "경로/문서명 규칙"과 8단계 "기획서 vs 실제 코드가
달라질 때" 분기 로직은 후보로 봤지만, 둘 다 해당 단계 자체의 핵심 판단 기준이라(그
단계를 설명하는 데 필수) 분리하면 오히려 "그 단계가 뭘 하는지" 이해하려면 다른 파일까지
같이 열어야 하는 역효과가 난다고 판단해 그대로 둔다.

## 변경 방식
- branch-workflow.md는 15단계 골격(각 단계 제목 + 1~3줄 핵심 요약 + 필요하면 위 4개 신규
  파일로의 링크)만 남긴다.
- 신규 파일들은 기존 문장을 그대로 옮기고 필요한 문맥(예: "이건 9단계에서 쓰인다")만
  살짝 보충한다 — **내용을 요약/축소하지 않는다**(이슈 본문 "내용 누락 없는지 확인" 조건).
- 다른 문서(CLAUDE.md, code-style.md 등)가 branch-workflow.md의 특정 섹션을 앵커/줄번호로
  직접 참조하는 곳이 있으면 새 파일 경로로 같이 갱신한다(아래 "영향 받는 기존 코드" 참고).

## 영향 받는 기존 코드
- `docs/rules/branch-workflow.md`(대폭 축소, 골격만)
- 신규: `docs/rules/progress-tracking.md`, `docs/rules/code-review-isolation.md`,
  `docs/rules/postman-collection-structure.md`
- `CLAUDE.md`, 다른 `docs/rules/*.md`가 branch-workflow.md를 참조하는 곳 확인 후 필요 시
  링크만 갱신(섹션 자체를 옮기는 게 아니라 링크 갱신이라 별도 승인 불필요, 참고용으로만
  기록)

## 리스크 및 고려사항
- **분리 기준이 다소 주관적**이다(어디까지가 "순서"고 어디부터가 "세부 규칙"인지). 위
  "분리 대상 확정"/"분리하지 않고 그대로 두는 것" 두 절에 판단 근거를 남겼다 — 다르게
  보는 지점이 있으면 검토 시 짚어달라.
- **"한 번에 하나의 기능만" 섹션을 진행 상태 추적과 합치는 판단**(위 2번)이 이견 있을 수
  있는 지점이라 별도로 표시해뒀다.
- 데이터/코드 동작 변경이 없어 QA는 "문서 링크가 다 살아있는지, 내용 누락이 없는지"
  확인으로 대체한다(10단계에서 다룰 예정).
